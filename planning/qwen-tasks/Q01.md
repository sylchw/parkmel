# Q01: Bounded inventory and offline readiness

Parent milestone: T02. Run only when the operator assigns Q01. This task creates inventory/state documents, not application code.

## Objective

In one short pass, record what exists and what local checks are possible. Existing application files do not require reading their contents for this task. Missing dependencies do not prevent completing this inventory.

## Read allowlist

1. Runner document, once.
2. This card, once.
3. Applicable `AGENTS.md` instructions, if present; check exact ancestor/root locations, not a recursive wildcard search. Honor any required instructions for the state write scope.
4. `state/CURRENT.md` if it exists, and root `package.json` only (maximum 120 lines).

Do not read the task index, README, documents 00–08, source files, Next/TypeScript/Vitest/Playwright configuration, tests, lockfile contents or Git history. Do not run Git commands if `.git` is absent. Prior transcript observations can be recorded as reported, but verify current filesystem facts in the single probe below.

## Single bounded environment probe

Use at most two read-only shell calls for this inventory. With shell tooling, collect the root listing; existence only of `state`, `.git`, `node_modules`, the common package-manager lockfiles and root config files; available `node`, `npm`, `pnpm`, `psql` and `docker` versions; and top-level `src` directory names. Cap output to 80 lines total. Do not search the home directory, dependency cache, processes, Docker images or running services. A CLI version is not proof of a running database/browser test environment. Mark those unverified unless operator evidence exists. If shell is unavailable, use a bounded root listing and existing supplied observations; record version checks as not-run.

Missing `state` → create it. Missing `.git` → record no Git metadata. Missing lockfile/node_modules → record offline build/test readiness blocked pending operator-supplied dependencies. Do not install, initialize Git or inspect source to resolve these findings.

## Write scope and immediate completion

Create/update only `state/CURRENT.md`, `state/environment.md` and `state/handoffs/Q01.md`. Record existing application/config filenames without claiming implementation completeness. Include versions actually observed, missing prerequisites, not-run checks and next candidate Q02 (pending operator assignment and its own preflight). Q01 may be `done` when the inventory is accurate even if Q02/build readiness is blocked. Never invent test results.

Keep each state file under 250 words. Once the listing/package read/probe are complete, write these three files immediately and end the run. Final answer: changed files, main readiness blocker and next suggested card, at most six lines. No application edits, more exploration or automatic Q02 execution.
